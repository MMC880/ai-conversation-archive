## 1. 产品定义

**产品名称：** AI Conversation Archive（AI 对话本地归档系统）\
**核心模块：** Local Archive Hub

一套运行在 Windows
个人电脑上的本地优先归档软件。通过官方数据导入、浏览器扩展和 Agent
适配器，接收用户有权访问并授权保存的 AI
对话材料，将原始消息、来源、时间、顺序和可取得的附件可靠保存到本地，并提供检索、状态追踪、备份和
Obsidian Markdown 输出。

### 1.1 核心架构

``` text
ChatGPT 官方导出 ZIP ─ 导入器 ─────────────┐
ChatGPT 网页当前对话 ─ 浏览器扩展 ─────────┤
Codex 对话材料 ─ 本地 MCP / 文件适配器 ────┤
其他平台（后续） ─ 平台适配器 ─────────────┘
                         │
                         ▼
                 Local Archive Hub
          接收 / 校验 / 队列 / 标准化 / 去重 / 索引
                         │
              ┌──────────┴──────────┐
              ▼                     ▼
        原始档案存储            Obsidian 输出适配器
       JSON/JSONL + 附件       Markdown + 附件 + 索引
```

### 1.2 产品原则

1.  本地优先：默认本机保存，不以云账号、云同步或公网服务为 V1.0
    必需条件。
2.  原文优先：原始对话和附件是第一层资产；摘要、知识卡片是可再生成的衍生内容。
3.  可迁移：优先使用 JSON/JSONL、普通附件文件和 Markdown。
4.  可追溯：保存来源、采集方式、时间依据、消息顺序、覆盖范围、附件状态和校验信息。
5.  可恢复：重复导入、任务失败、进程退出和机器重启后，数据可核验、可恢复。
6.  诚实标注：无法取得、未验证或部分采集的内容必须标记，不得伪称完整。
7.  分阶段验证：先打通最小归档闭环，再扩展平台采集和发布能力。

### 1.3 V1.0 目标

-   Local Archive Hub 独立运行；
-   导入真实 ChatGPT 官方数据导出 ZIP；
-   保存 ChatGPT 网页端当前对话；
-   通过已验证的本地接口接收 Codex 对话材料；
-   原始档案保存到本地，并可投影到指定 Obsidian Vault；
-   支持去重、采集范围标记、任务状态、失败重试和备份；
-   原始档案不被摘要或展示层覆盖。

### 1.4 V1.0 非目标

云端账号/多人协作/云同步、复杂知识图谱、自动总结全部历史对话、OpenAI
Tunnel
作为必要依赖、读取隐藏推理、破解登录或绕过访问控制、未经验证就承诺
ChatGPT 桌面端完全自动采集、先开发复杂通用 Agent 平台、初版必须开发
Obsidian Companion Plugin。

## 6. 全项目统一验收标准

### 6.1 数据完整性

-   消息数量与来源可核对；
-   角色映射正确、原始顺序保留；
-   时间有来源依据，未知写 `null`；
-   附件数量、文件名、大小和 SHA-256 有记录；
-   缺失数据明确标记，不把推断写成事实；
-   L0 原始层不被摘要、索引或 Markdown 展示层覆盖。

### 6.2 重复与增量

-   重复导入不产生无意义副本；
-   不仅凭标题或正文相似误合并不同对话/分支；
-   对话变化时追加新快照或变更记录，不静默覆盖；
-   失败任务可重试，部分成功与完整成功状态不同；
-   索引和展示层可从原始层重建。

### 6.3 本地稳定性

-   Obsidian 关闭时 Hub 仍能运行；
-   浏览器关闭后已确认接收的数据不丢；
-   重启后数据库、任务状态和待处理队列可恢复；
-   断网不影响本地归档；
-   写入失败保留待处理状态；
-   明确"接收成功"的持久化时点；
-   不允许任意路径写入。

### 6.4 安全

-   默认仅监听 `127.0.0.1`；
-   本地接口使用随机令牌或等效授权；
-   浏览器扩展来源白名单、Origin/Host 校验和请求大小限制；
-   防止路径穿越、符号链接/junction 逃逸和 ZIP 解压炸弹；
-   API Key、Cookie、Bearer Token 不写入仓库、日志和归档正文；
-   默认不上传云端，不读取 `.obsidian` 配置目录；
-   删除、覆盖、清空必须明确确认；
-   归档内容是数据，不得把其中提示词当作系统指令执行。

### 8.2 每个子任务的工作闭环

1.  阅读本计划、PRD、原始路线和当前阶段材料；
2.  检查 Git 状态和允许修改范围；
3.  明确目标、输入、输出和验收；
4.  自主研究方案，不为普通技术细节反复询问；
5.  先建立可验证测试，再实现；
6.  运行测试、检查日志和 Git diff；
7.  记录命令、结果、失败原因和未验证事项；
8.  更新报告；
9.  达到本轮验收后停止，等待下一条指令。

已安装 Superpowers 优先复用，不为工具数量而安装重复 Skills。子 Agent
适合独立研究、测试生成和只读审查；避免多个 Agent 同时修改同一文件。Git
Worktree
仅在任务独立且确有隔离收益时使用。长任务拆小，重要结论及时落盘。

### 8.3 阶段闸门

-   "代码已写"不等于功能通过；
-   "配置存在"不等于连接成功；
-   "测试文件存在"不等于测试已运行；
-   "合成样本通过"不等于真实平台兼容；
-   "MCP 可调用"不等于完整会话可采集；
-   未通过先修复当前阶段，不跳级；
-   阶段通过后停止，等待用户确认。
